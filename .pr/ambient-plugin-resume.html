SDK · PERSISTED CONVERSATIONS

Reconcile plugins without deleting caller configuration

Ambient contributions are removed only after a complete discovery scan and only when the conversation has a record of owning them. Replacement agents and legacy data are not subjected to guessed ownership.

A failed scan preserves the previous contribution snapshot. Recovery performs normal reconciliation on the next load. local_conversation.py:1032

API and compatibility

BeforeAfter
load_available_plugins(...)load_available_plugins(..., strict=False)

The keyword is additive and defaults to existing best-effort behavior. Conversation reconciliation explicitly requests strict discovery. Persisted field shapes remain unchanged in this repair. Sources: discovery.py:170 · state.py:157

Legacy conversations without ownership records may retain stale plugin content. Deleting it by matching names can delete caller configuration. Existing same-name overrides cannot be reconstructed from an already merged saved agent. Persisting the pre-ambient agent remains a separate design option.
