Spread LLM retries within existing wait bounds

Issue #6938 reports callers retrying together against finite backend capacity. The SDK's deterministic exponential waits preserve that correlation.

The shared LLM retry factory passes the new field to synchronous/asynchronous Chat Completions and Responses. No error classifiers, stop conditions, attempt counts, timeouts, provider routing, server or TypeScript contracts change. Old JSON loads with the new optional default; no schema migration is required.

Real HTTP comparison

The reproducer runs 24 callers against a loopback HTTP server with four admission slots and 0.3-second service time. Each entry point runs three trials, with real LiteLLM transport and real sleeps. Both revisions use four attempts and scaled 1/2/4-second exponential waits.
