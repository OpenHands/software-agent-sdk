Agent-server design note · issue #3979

Prewarm the server-owned profile skill catalog

Profile launches already resolve skills through the agent server. This change moves the public catalog's cold Git clone from the first profile launch into server startup, while keeping offline startup nonfatal and providing an explicit opt-out.

1The first launch no longer owns catalog setup

★ Readiness now means the profile skill catalog has had its best-effort warmup attempt. A real cold-start run cloned OpenHands/extensions and loaded 60 skills before Uvicorn reported application startup complete.

The existing profile path remains authoritative: discover_profile_skills() still builds the user + public catalog. Startup simply invokes the same function early; there is no second catalog, bundled snapshot, or alternate merge rule. Sources: skills_service.py:435-475.

2Clone and parse shift before readiness

3The startup behavior is explicit and reversible

Before

Config
  preload_tools: bool = True

# No profile catalog warmup.
# First profile launch initializes it.

After

Config
  preload_tools: bool = True
  prewarm_profile_skills: bool = True

# Opt out:
OH_PREWARM_PROFILE_SKILLS=0

The change is additive. Existing configurations remain valid; operators that require immediate offline startup can disable the warmup. Source: config.py:322-332.

6Startup pays the network cost once

⚠ This deliberately moves clone latency to startup. It does not remove network cost, pin OpenHands/extensions, or change the 60-second refresh policy for mutable refs.

Three guardrails keep the trade-off bounded: the blocking Git work runs in asyncio.to_thread, a failed clone cannot brick startup, and OH_PREWARM_PROFILE_SKILLS=0 restores lazy behavior. The same startup path also runs for deferred-init pods, allowing their dormant warm-pool period to absorb catalog setup.
