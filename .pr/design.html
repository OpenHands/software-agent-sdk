Background tasks in TaskToolSet

Explicit background execution lets a parent agent launch independent sub-agent conversations, keep working, then read or stop them through native tools. Existing blocking task and resume behavior remains the default.

Owner: TaskToolSet + TaskManager Scope: process-local runtime lifecycle Cancellation: LocalConversation.interrupt() Related: unblocks #2186 background work

Why the implementation owner changed

The old path

DelegateExecutor is a lower-level legacy path, while the supported sub-agent tool surface is TaskToolSet.

The current path

TaskToolSet is registered by defaults, settings, and examples. Its existing TaskManager already owns sub-agent conversations, persistence, resume, confirmation, and metrics.

The change extends the authoritative owner. It does not keep a second background registry beside the supported task tool, and the existing Delegate implementation stays unchanged. This is an explicit API-surface decision: this candidate does not add background lifecycle commands to DelegateAction.

One manager, one lifecycle

TaskToolSet

Creates all three tool definitions together.
→

Shared TaskExecutor

Dispatches action types and closes only once even when the parent closes three tools.
→

Shared TaskManager

Owns registry, conversations, worker threads, result settlement, and cleanup.

A manager binds to its first parent conversation. Managers attached to the same parent share only a small ID/metrics lock. New managers continue after persisted task metric IDs, and each task reserves its task:{task_id} usage slot before a worker can settle, preventing ID reuse and structural metrics mutations from background threads.

Task state machine

Poll is read-only

Repeated task_output calls return stable snapshots and never re-extract output or merge usage.

Stop is ordered

If completion settles first, stop rejects completed/error. If stop reserves first, the terminal state is cancelled.

Resume is explicit

Only a settled terminal task may resume with the same ID. Active and terminal-but-settling tasks reject resume so one conversation is never replaced underneath its worker.

Execution and exactly-once settlement

Background run

Parent
Calls task(run_in_background=True).
Manager lock
Allocates task and conversation, reserves its parent metrics slot, publishes queued, and starts one managed daemon worker.
Worker
Sets running, sends the prompt once, then calls asyncio.run(LocalConversation.arun()).
Conversation
Retains existing confirmation, hooks, agent definition, visualizer, persistence, budget, and event behavior.
Settlement
Extracts final output once, stores terminal state, replaces the reserved cumulative metrics slot once, closes the conversation, and signals both completion and any blocked output readers.

Settlement guard

with manager_lock:
    if task.settlement_started:
        return
    task.settlement_started = True

settle_metrics_once()
pause_and_close_conversation()

with manager_lock:
    archive_without_live_conversation()
    task.settled = True
    task.completion_event.set()
    task.wait_event.set()

The guard covers natural completion, response-extraction failures, stop, partial thread-start failure (including BaseException), and close races. A separate lifecycle wait event wakes blocked output readers on stop or manager close; completion_event remains the final-settlement signal.

Cooperative stop and bounded close

task_stop

Manager
Sets stop_requested under the registry lock.
Conversation
interrupt() cancels the tracked async task on its event loop and signals the existing cancellation token.
Worker
Observes the stop request, records cancelled, and runs normal settlement.
Caller
Waits at most five seconds across completion and join. No Python thread is force-killed.

executor / parent close

Close
Marks the manager closed so no new task can publish.
Close
Requests stop for every active task and interrupts each conversation.
Close
Uses one shared five-second deadline, then joins all known task workers.
Cleanup
Clears registry and temporary storage only after every task has settled.

If an external dependency ignores cooperative cancellation past the deadline, close returns without destroying state underneath the live worker. The registry and temporary directory remain owned until that worker exits; its final settlement completes cleanup later.

Compatibility and persistence boundary

Preserved
  • Blocking task is still the default.
  • Completed task resume remains available.
  • Confirmation handler and inherited confirmation policy.
  • Agent definition hooks, iteration/budget limits, prompt cache key, and visualizer.
  • Parent subagents/ persistence layout and task:{task_id} metrics keys.
  • Workflow and existing Delegate callers remain source-compatible; DelegateAction does not gain new lifecycle commands here.
Intentionally process-local
  • Registry records, worker threads, events, and stop handles are not serialized.
  • A new process or manager reports an old task ID as unknown.
  • Persisted conversation history does not claim that a worker survived restart.
  • Normal manager close preserves parent-owned persisted conversation data.

Verification evidence

Focused coverage is in tests/tools/task/test_background_task.py; existing task, delegate, workflow, and conversation tests remain part of the affected suite.

Scheduling

Event-gated immediate return, queued-to-running-to-completed, two independent workers, active resume conflict, parent binding.

Failure

Agent and response-extraction exceptions, unknown ID, timeout bounds including NaN/infinity, terminal stop, and transactional thread-start rollback.

Cancellation

Queued stop, running stop, repeated stop, real LocalConversation interrupt, interrupt failure containment, and stop/close ordering.

Cleanup

Executor close, parent close, post-close reuse rejection without allocation, uncooperative deadline, deferred cleanup, and no residual Task-* worker.

Accounting

Final response and metrics exactly once, repeated output, two managers sharing a parent without ID/usage collision, and parent stats iteration during worker settlement.

Boundary

Blocking compatibility, settled background resume, confirmation flow, persistence restart behavior, hooks/definitions/visualizer through existing tests.
