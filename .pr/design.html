Conversation errors keep their origin

Two TypeErrors from different SDK functions no longer collapse into one class. Error events gain an optional module/function origin and a stable grouping_key. User-facing classification is unchanged, and the telemetry fingerprint still hashes module and line.

1What changed

★ Additive and privacy-bounded. origin and grouping_key are optional, default null, and are built only from dotted identifiers. Exception text, paths, and secrets never enter them. error_origin.py:1

19 files · +716 / −42. The behavior change is the new derivation module plus two event fields. Call sites only pass the caught exception into that derivation. Older payloads that omit the fields still validate.

2API before → after

Compatibility: additive. Missing fields default to null. extra="forbid" is unchanged, so unknown keys still fail, and events written by this version still load on older readers that ignore unknown JSON keys only if those readers are lenient — strict old clients that reject unknown properties will see the new keys. In-repo clients use the current models.

grouping_key is blake2s-16 over origin|code (32 hex chars). When a conversation event omits the key, the model fills it from origin and code. A supplied 32-char hex key is kept. Agent events never fill the key themselves: error is the message, so the producer passes the digest of the exception class name.

5Origin derivation

origin_from_exception

Prefers the innermost openhands.* frame, so a library raise is attributed to the SDK caller. If the traceback never enters OpenHands, the innermost frame is kept and its module is collapsed to the top-level package. Identifiers that fail the dotted-name grammar (paths, <lambda>, <locals>, secrets) are dropped. An origin longer than 96 characters is omitted rather than shortened to a shared suffix. Nameless traceback links do not consume the 256-frame yield budget. Line numbers are not part of the origin, so the same function stays stable across unrelated edits.

6Event models

8Risk

The checked-in TypeScript schema is generated from the published v1.55.1 OpenAPI artifact, and that contract is already released. Regenerating it in this PR would fail check:agent-server-api. This branch's OpenAPI export does include the new nullable fields (make test-server-schema passed). The client types pick them up on the next version-bump regeneration.

Strict consumers that reject unknown JSON properties on events will see origin and grouping_key. Both are optional and null when no traceback is available. Telemetry ErrorFingerprint values are covered by the existing sanitizer tests and were not retargeted.
