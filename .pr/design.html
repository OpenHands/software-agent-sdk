Pause requests remain active until the step stops

An ACP step is a whole remote prompt turn. Tools may keep running after /pause; the API must expose that interval instead of reporting completion.

1. Contract2. Responsibilities3. Evidence

1. Distinguish the request from completion

Compatibility remains unresolved. Older Python clients reject pausing. The existing capability checks do not negotiate response enums. Before upstream release, agree a rollout or opt-in contract satisfying the five-minor-release policy. This fork draft is not ready for upstream submission.

Pause completion · Baseline pause()

2. Keep status consumers consistent

ResponsibilityChange and reason
Run loopsTrack pause intent and complete it at a step boundary. Repeated requests do not duplicate PauseEvent. IDLE pauses immediately.
Native confirmationReject an action superseded by a new message before pausing. Otherwise preserve WAITING_FOR_CONFIRMATION, so resume is not presented as approval.
ACP finalizationKeep PAUSING until cleanup completes. Record successful completion separately so interruption during cleanup cannot replay the prompt.
Remote waitingHTTP polling and WebSocket updates keep waiting during PAUSING. Concurrent /run remains HTTP 409.
Startup recoveryReuse active-state recovery for stale PAUSING. Catalog startup loads those records; they become ERROR without automatic replay.
Runtime retentionExclude PAUSING from idle eviction. RUNNING and PAUSING share is_active().
API types and docsAdd the Python/handwritten TypeScript enum value and describe the boundary. Generated TypeScript schema stays tied to its released server image pin.

3. Verify behavior before and after

  • HTTP/WebSocket ACP regression: baseline reports paused while shell writes continue; fixed behavior waits, pauses, and resumes without replay. A second case interrupts post-response cleanup.
  • Native confirmation regression: both cases fail against d3a47c336 and pass after the fix. The tests reuse existing streaming/confirmation fixtures.
  • Python: 2206 passed, 6 deselected, 52 warnings. The suite also reports an unawaited-coroutine warning; it is not warning-clean.
  • TypeScript is unchanged in this optimization: prior validation had 396 tests, build and changed-file ESLint passing; full ESLint had 3 errors in unchanged integration tests.
  • Earlier real SIGKILL/restart check: PAUSING → ERROR in catalog and direct GET; one prompt and one shell write remained, with no automatic replay. Recovery code is unchanged in this optimization.
