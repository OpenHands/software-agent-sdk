Run the summarizing condenser on its own LLM profile

Adds llm_profile_ref to LLMSummarizingCondenserSettings, resolved at launch into an embedded llm — #5469.

compat: additive no schema_version bump defaults unchanged one field: ref on condenser settings

1 · Problem, in one line

build_condenser() copies the agent's own LLM (usage_id="condenser"), so compaction always runs on the model driving the agent loop. Users on local hardware want the split the pre-SDK server supported (llm_config = "condenser_llm"): a strong model thinking, a cheap fast model summarizing.

2 · The shape (as agreed in the issue thread)

Before

One LLM for everything

class LLMSummarizingCondenserSettings:
    enabled, max_size, max_tokens,
    keep_first, minimum_progress, ...

# build_condenser():
condenser_llm = llm.model_copy(
    update={"usage_id": "condenser"})

The condenser is structurally welded to the agent model. Switching the agent model mid-session also switches the summarizer — the only way to get a cheap condenser was to cheapen the whole agent.

After

Opt-in dedicated summarizer

class LLMSummarizingCondenserSettings:
    ...
    llm_profile_ref: str | None = None  # portable ref
    llm: LLM | None = None               # launch-resolved

# build_condenser():
if self.llm is not None:
    condenser_llm = self.llm  # keeps its usage_id
else:
    condenser_llm = llm.model_copy(
        update={"usage_id": "condenser"})  # unchanged

Unset = byte-for-byte the old behavior. Set = summarize on the named profile, survive agent model switches.

Two fields, one story. llm_profile_ref is what a user writes and a profile stores (secret-free, portable). llm is the resolved payload the launch embeds — exactly the meta_profile_ref → meta_profile_llms precedent already in this codebase. Keeping build_condenser(self, llm) store-free preserves the invariant that a resolved AgentSettings runs without the profile store; the settings own the LLM they consume.

3 · Data flow, grounded to the code

 OpenHandsAgentProfile.condenser.llm_profile_ref = "cheap"   (secret-free at rest)
        │
        ├─ launch/resolve.py  _resolve_openhands()
        │     condenser_ref == profile.llm_profile_ref → no-op (condenser already follows agent)
        │     else _load_llm(stores, "cheap")  →  missing ⇒ UnresolvedProfileReferences
        │                                             .condenser_llm_profile_ref="cheap"  (reported with all other dangling refs)
        │
        ├─ profiles/resolver.py  _build_openhands_settings(condenser_llm=…)
        │     embeds: condenser.llm = loaded LLM (usage_id="cheap" = store-key marker)
        │     resolved settings stay store-free ✔ (mirrors meta_profile_llms)
        │
        ├─ profiles/resolver.py  resolve_agent_profile() + resolve_agent_profile_dry_run()
        │     legacy resolver and editor preview get the same resolution
        │     diagnostics: condenser_llm_profile_ref / condenser_llm_profile_resolved
        │
        └─ settings/model.py  create_agent() → build_condenser(llm)
              condenser = LLMSummarizingCondenser(llm=condenser_llm, …)
              max_tokens inherits the condenser LLM's effective_max_input_tokens (was: agent's)
              usage_id collision with the agent LLM → re-keyed to "condenser"
              (same dedup rule as subagent/registry.py)

4 · The interactions this change had to answer

InteractionBehavior
switch_llm() while a dedicated condenser LLM is set The existing guard (condenser_config != current_config) already recognizes a condenser on a different config and leaves it alone — this PR adds a regression test pinning exactly that; no change to the conversation code. A condenser following the agent is refreshed as before.
Ref names the agent's own LLM profile No-op at resolve time: no second store read, usage_id="condenser" dedup key kept instead of duplicating the agent's registry key.
Dangling ref Launch fails with UnresolvedProfileReferences — to_detail() gains dangling_condenser_llm_profile_ref (additive JSON key), reported together with the existing dangling refs.
Token-budget inheritance Unset max_tokens now inherits from the model that actually summarizes, not the agent. This is the fix's safety property: a 64k summarizer must not be handed a 1M agent window. (For the default path both are the same object, so the change is inert unless the split is on.)
Secret-free-at-rest profiles A profile-level field_validator("condenser") strips any embedded llm on ingest — the ref survives, the payload doesn't. Every write path (save(), rename, direct validation) inherits the guarantee.
Persisted conversation settings The embedded LLM round-trips like the top-level llm: the agent-server's _SecretProbeCipher sees its key (probe returns True, verified locally), so a settings row carrying it is encrypted at rest; a no-expose dump redacts it. No golden-fixture or migration changes — additive, both fields nullable, exclude_none=True dumps omit them for existing producers.
Settings schema export / GUI condenser.llm_profile_ref exports (label "Condenser LLM profile", MAJOR prominence, depends_on enabled); condenser.llm carries no field metadata and stays internal — matching how meta_profile/meta_profile_llms are treated.
Sub-agents / AgentDefinition Untouched by design: sub-agents take a concrete CondenserBase (frontmatter), not settings; they already support a distinct model via agent_def.model + their own condenser path. Extending refs there is a separate concern.

5 · Config example

# profile (saved via the profiles store — ref only, no credential)
condenser:
  condenser_kind: llm_summarizing
  llm_profile_ref: cheap     # ~/.openhands/llm-profiles/cheap.json

# resolved (embedded at launch — runs without the store)
condenser:
  condenser_kind: llm_summarizing
  llm_profile_ref: "cheap"
  llm: { model: "litellm_proxy/ollama/qwen3:4b", usage_id: "cheap", … }

6 · Compatibility statement

  • Additive Python API. Two optional fields on a settings model, all with default=None → existing construction, serialization, and dumps are unchanged. No removals, no renames, no behavior change on the default path.
  • No schema_version bump. Old payloads (v5–v8 baselines) load unchanged; verified against the golden-fixture + PyPI 1.51.0 baseline checker (check_persisted_settings_compat.py passes as-is).
  • Server contract additive. llm_profile_ref/llm (both null by default); UnresolvedProfileReferences.to_detail() gains one key; diagnostics gain two fields. clients/typescript regenerates from the release OpenAPI artifact via the normal bump flow — no handwritten interface changes are required (the condenser surface is already unknown passthrough there).
  • Tests: 25 new — settings/build level (fallback, split, copy-semantics, re-key, budget inheritance, validation mismatch), launch (resolve() embed/no-op/dangling), legacy resolver + dry-run diagnostics, store round-trips, and 3 conversation-level switch-preservation regression tests. Full SDK suite: 6852 passed; agent-server profile/settings/switch/condenser: 474 passed.
