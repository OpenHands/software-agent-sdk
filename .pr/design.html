Wait once. Receive the child's result.

One server-owned wait coordinates existing direct children without a browser. Results use one durable typed mailbox; agent tools release their parent's state lock.

Data flow

Parent Agent → wait_for_children → canonical REST wait
                         ↓ release parent state lock
Child run + stop hooks → immutable run outcome
                         ↓ canonical typed mailbox
Parent persisted MessageEvent ← final result
                         ↓ optional generation-guarded cleanup
Parent tool observation ← status + mailbox_message_id

Canonical operations

POST /api/conversations/{parent_id}/children/wait
{ "conversation_ids": ["child UUID"], "timeout_seconds": 60,
  "delete_on_finish": false, "on_timeout": "retain" }

POST /api/conversations/{sender_id}/mailbox
{ "recipient_id": "recipient UUID", "idempotency_key": "stable-key",
  "kind": "review-request", "body": "Review commit abc",
  "evidence": ["commit abc; passing test run"], "delivery": "steer" }

Waits accept 1–64 unique direct children and finite timeouts of 0–300 seconds. Timeout is a normal result. Policies retain, stop or delete pending children; settled results reach the mailbox before requested deletion.

Lock and cancellation ownership

Each request owns its child waiters and parent-interruption waiter, pins runtimes and drains owned tasks. Per-run immutable snapshots prevent successor results and cleanup from being confused. HTTP disconnect releases waiters without cancelling the child.

Coordination tools run in isolated groups outside the conversation state lock. Their executors own async HTTP clients; interruption cancels and drains those workers before the parent lock is reacquired. Ordinary tools keep their existing locking and parallel execution behavior.

One mailbox delivery path

The existing persisted event log owns delivery and deduplication. Deterministic sender/recipient/key identities return the same ID on replay and reject conflicting payloads. Agent-origin metadata is explicit; it is never attributed to a human. The sender and recipient secret registries redact content before persistence.

Steer is consumed at step boundaries without killing work or active goals. Idle recipients pick up durable input on their next run after restart. Explicit interrupt records the sender, mode and reason and persists interrupted goal status. No queue mode, scheduler, second spawn registry or bespoke result event is introduced.

Compatibility and validation

Existing request defaults and persisted events remain readable. APIs and optional event metadata are additive; no package version changes. TypeScript exposes typed methods and mailbox events while its generated release pin remains unchanged.

See .pr/VALIDATION.md for passing deterministic and real HTTP tests, original CLI doctor/API probes, baseline-reproduced environment failures, compatibility evidence and checks that remain unrun.

Practical limits

The deadline covers waiting after loading; cleanup may extend total request duration. Arbitrary legacy synchronous workers remain cooperatively interruptible. Coordination is on one backend. Canvas UI, live-model evaluation and packaged runtime verification remain separate lanes.
