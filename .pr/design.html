OpenHands/software-agent-sdk · additive backend API · Refs #6129

Wait once. Let children keep running.

Partial scope: state/lifecycle waiting is implemented. Mailbox finish-result delivery (#6127) and an SDK agent tool remain integration work. This is not a full fix for #6129.

Before

A parent coordinates separate child conversations with repeated status requests or agent turns. The server exposes launch, but has no bounded child-wait operation.

After

One authenticated HTTP request awaits existing children using lifecycle events and per-run futures. No browser or WebSocket is required. The response contains status, settlement and cleanup outcomes.

Additive interface

POST /api/conversations/{parent_id}/children/wait
{
  "conversation_ids": ["child UUID", "another child UUID"],
  "timeout_seconds": 60,
  "delete_on_finish": false,
  "on_timeout": "retain"
}
InputContract
conversation_ids1–64 unique existing direct children; immutable parent link is the authority.
timeout_secondsFinite 0–300 seconds; default 60. Starts after validation and runtime loading.
delete_on_finishDefault false. Cleanup skips a child whose run restarted.
on_timeoutretain (default), stop, or delete. Stop/delete use existing lifecycle methods.
{
  "children": [{
    "conversation_id": "child UUID", "execution_status": "finished",
    "settled": true, "deleted": false
  }],
  "timed_out": false, "interrupted": false
}

Statuses are captured before requested cleanup. FINISHED, ERROR, STUCK, explicit PAUSED and DELETING settle the wait. Unknown parent or non-child: 404. Invalid body: 422. Session authentication remains unchanged.

Lifecycle and ownership

  1. ConversationService.wait_for_children validates every ID against the existing catalog before loading children.
  2. EventService mirrors execution-status lifecycle notifications on the event loop. A new run allocates its own completion future and generation. Final status is captured after the run and stop hooks settle.
  3. Each request owns one waiter per child and one parent-interruption waiter. Idle runtimes are pinned by counters, with no state or lifecycle locks held during the wait.
  4. The deadline, a parent pause/interrupt/close, HTTP disconnect or caller cancellation settles or cancels those waiters. Cancellation does not propagate into child run futures.
  5. Started destructive cleanup is shielded and drained. Cleanup checks the captured run generation; conditional deletion fences new runs atomically before teardown.

No child registry, message queue, scheduler, persistent workflow or result-delivery event is introduced.

Compatibility and remaining integration

  • Existing REST operations, persisted settings and SDK event unions are unchanged. No package version is bumped.
  • TypeScript adds ConversationClient.waitForChildren and typed models, caller AbortSignal support and a transport timeout above the requested wait.
  • The checked-in generated schema stays at its documented v1.58.1 release pin. The documented generator was also run against the local new OpenAPI schema into temporary PR evidence. Generated aliases can replace the handwritten models when the pin advances.
  • No finish text is returned or injected. #6127 owns mailbox delivery. Deleting a child now removes its history; use retention if a later consumer still needs its result.
  • A regular native SDK tool executes while its parent holds ConversationState. Adding a synchronous HTTP wait there would violate #6129. A lock-releasing, cancellable agent-tool integration is deliberately not claimed here.
  • The wait deadline excludes runtime loading and lifecycle cleanup. Legacy synchronous workers retain their existing cooperative interruption limits. Cross-instance / cross-container coordination is outside this same-backend primitive.

Validation

Deterministic tests use explicit events for completion, pre-completion, multiple children, failure, timeout, cancellation, cleanup, held locks and restart races. A real uvicorn HTTP test exercises session authentication, client disconnect, parent progress and completion without any WebSocket.
