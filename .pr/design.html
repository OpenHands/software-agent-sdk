Typed LLM boundaries

One SDK PR for #4976. Provider variability stays at private boundaries; public messages, events, configuration, and return types stay unchanged.

Completion rule

observed = initial wrapper completion, if present
for each event:
    retain any yielded completion
    collect finished output items and dispatch deltas
final = non-null wrapper completion or observed
if no final completion: raise LLMNoResponseError

An empty final output can still be reconstructed from finished output items. Raw response identity and per-output-item delta IDs are preserved. The rule follows alanhuangyoo's #4772.

Private modules

  • _response_stream.py: recognize supported events and select completion state.
  • _tokenizer.py: optional loading and supported token-count shapes.
  • _message_normalization.py: normalize metadata and Responses output items.

LiteLLM deletes absent reasoning/thinking fields despite declaring them in its message type. A small projection with defaults handles this explicitly. Typed tool-call objects keep their existing validation path; generic objects and dictionaries retain the existing default values.

Compatibility and scope

No dependency changes, public schema changes, agent-loop changes, provider routing changes, or retry/telemetry cleanup. Synchronous streams returned to asynchronous callers still drain in the existing executor path. Transformers remains optional. The dynamic-access baseline shrinks by 14 entries (98 to 84).

Verification

Regression coverage includes completion precedence, supported wrapper modes, output reconstruction without callbacks, replay IDs, encrypted reasoning, thinking blocks, token-count shapes, and authentication restoration.

Six real loopback HTTP/SSE cases pass through SDK and LiteLLM parsing. Optional tokenizer checks pass both without Transformers and with Transformers 5.17.0 loading a local tokenizer. See verification.md for exact commands, suite results, and environmental limitations.
