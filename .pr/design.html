Non-blocking background subagent execution

An additive lifecycle for DelegateExecutor: explicit background delegation returns stable task IDs immediately, while the parent can poll status, retrieve output, or cooperatively stop a task. This implements issue #2047 and unblocks the background item in #2186.

Additive API background=False by default Per-executor, in-process registry LocalConversation owns execution Cooperative cancellation only

The registry does not replace conversation state. It records task identity and a five-state lifecycle; LocalConversation.arun(), its event history, and its metrics remain authoritative for execution, output, failure, and cancellation.

Before / after API

Before — always blocking

observation = executor(
    DelegateAction(
        command="delegate",
        tasks={"researcher": "Trace the call path"},
    ),
    parent,
)
# Returns only after the subagent thread is joined.

After — blocking remains the default

started = executor(
    DelegateAction(
        command="delegate",
        tasks={"researcher": "Trace the call path"},
        background=True,
    ),
    parent,
)
task_id = started.task_ids["researcher"]

executor(DelegateAction(command="status", task_id=task_id), parent)
executor(DelegateAction(command="output", task_id=task_id), parent)
executor(DelegateAction(command="stop", task_id=task_id), parent)

Task state machine

Linearization: a stop that reserves the task before terminal settlement wins and produces cancelled. Polling never mutates state. A completed or failed task rejects a later stop; stopping an already-cancelled task is idempotent success.

Ownership and concurrency

Executor-owned registry

  • One registry per DelegateExecutor, bound to its first parent conversation.
  • A re-entrant lock guards task records, task ID publication, and agent reservations.
  • One active reservation per agent ID prevents two tasks from mutating the same LocalConversation.
  • Different agent conversations receive independent daemon worker threads and may run concurrently.

Conversation-owned execution

  • Workers call send_message() once, then run arun().
  • Existing confirmation handling repeats asynchronous runs at confirmation boundaries.
  • Final output is extracted once from the conversation event history.
  • Cumulative subagent metrics replace delegate:<agent_id> once at terminal settlement.

Start, stop, and cleanup sequences

Start path

Parent agent
delegate(background=True) with an agent → prompt map
Executor lock
Validate agent IDs, reject active conflicts, allocate UUID task IDs, reserve conversations
Registry
Publish queued records before starting workers
Worker
Transition to running; call send_message() and async conversation execution
Parent agent
Receive task_ids without joining the worker

Stop / close path

Parent agent
stop(task_id) marks stop_requested
Executor
Call existing LocalConversation.interrupt(); never kill a Python thread
Conversation
Cancel tracked arun task, signal tool cancellation token, emit interrupt event, enter PAUSED
Worker
Settle result/metrics once, release agent reservation, transition to cancelled
Executor
Join cooperatively. close() shares one 5 s deadline across all workers, then closes conversations.

Python threads are not force-killed. If an external confirmation callback or dependency ignores cooperative cancellation past the deadline, cleanup logs a warning and returns; daemon status prevents that worker from holding process exit. Normal LocalConversation cancellation is verified to leave no worker thread alive.

Compatibility and persistence boundary

Preserved

  • spawn and blocking delegate behavior; background remains opt-in.
  • max_children, agent type resolution, definition hooks, permission mode, and inherited confirmation policy.
  • Parent visualizer sub-visualizers and parent subagents/ persistence layout.
  • Cumulative metrics replacement, avoiding repeated usage accumulation.

Explicit boundary

  • Task registry entries are runtime control handles, not conversation events or persisted settings.
  • A fresh process or executor cannot resolve old task IDs and returns “not found”.
  • Persisted subagent conversations remain where they were; no false promise of restoring worker threads is added.
  • Reusing an executor with another parent conversation is rejected.
