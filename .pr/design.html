Public OAuth callbacks for hosted Agent Server

OAuth MCP installation currently registers a FastMCP loopback redirect such as http://localhost:<port>/callback. That only works when the browser can reach the agent process. A hosted agent needs its configured public origin instead.

Interface

When OH_WEB_URL is unset, the existing local callback and authenticated POST /api/mcp/oauth/callback/{job_id} flow are unchanged. When it is set, OAuth client registration uses: 

GET {OH_WEB_URL}/api/mcp/oauth/callback/{job_id}?code=...&state=...

The route is intentionally public: an authorization server redirect cannot carry the agent session API key. Access is constrained by an unguessable probe job ID and the state generated for that specific authorization request. This is an additive endpoint; no existing request or response schema changes.

Flow

Start OAuth probe
→
Register public redirect URI
→
Browser authorizes and redirects
Public route validates job + state
→
Waiting FastMCP client receives code
→
Existing token exchange and status flow

Failure handling

  • Unknown or expired job: 404.
  • Callback before the client is waiting: 409.
  • Missing or mismatched OAuth state: 400, without waking the job.
  • Provider error redirects wake the job with a generic failure; provider text is not reflected into HTML.

Compatibility and verification

The implementation changes FastMCP client metadata after its normal initialization rather than copying its private binding implementation. Both dynamically registered and pre-registered clients use the public callback URI. Tests cover the configured path prefix, local-flow preservation, session-key-free public delivery, ready-state checks, state isolation, and expiration.
