Conversation session IDs through an OpenRouter proxy

Addresses the session-ID forwarding portion of #6283. Tool-argument recovery, provider telemetry and stuck detection are outside this change.

Problem and behavior

The existing auto-detector sees the proxy alias and URL, so it cannot identify an upstream OpenRouter route. In the recorded public Conversation workflow, the baseline sends its conversation header but omits body session_id. An explicit option makes that topology configurable without storing dynamic state on a shared LLM.

llm = LLM(
    model="litellm_proxy/your-openrouter-alias",
    base_url=proxy_url,
    send_session_id_in_body=True,
)
ValueAutomatic body injection
None (default)Retain existing direct-OpenRouter detection.
TrueUse the current conversation ID if available.
FalseDisable automatic injection, including direct routes.

Explicit body IDs remain authoritative in every mode. No context means no generated ID. Existing header and prompt-cache-key behavior remains unchanged.

State ownership and compatibility

Conversation ID → immutable LLMCallContext → Agent step/astep → shared chat/Responses options policy → copy-on-write extra_body → configured proxy

Only configuration lives on the LLM. Both options builders use the same helper and existing context injection. The nullable field is additive and defaults to the previous behavior. Profiles and persisted agent settings preserve the option; old payloads keep their old behavior. No dependency lock, schema migration or package version is changed by this feature.

A model-capability override was considered but not implemented: this is a transport-topology policy, and existing auto-detection is sensitive to the endpoint URL. The public field name and tri-state policy remain explicit review choices.

Reproduce

From the SDK repository root after installing its development dependencies:

LITELLM_LOCAL_MODEL_COST_MAP=True OPENHANDS_SUPPRESS_BANNER=1 \
  .venv/bin/python .pr/session-affinity/reproduce_proxy_session.py \
  --enable-body --output /tmp/candidate-sync.json
# Add --asynchronous for the asynchronous workflow.

For the baseline, copy this helper outside the checkout, use the recorded upstream revision in a separate checkout/environment, omit --enable-body, and run it with that checkout as the current directory. It saves the request report before the expected assertion failure. The helper uses loopback endpoints and literal test keys.

Limits

This verifies SDK serialization and Router/adapter forwarding against local HTTP endpoints. It does not run the complete LiteLLM proxy_server, call real OpenRouter, or measure cache/cost gains. Proxy auth/hooks/preprocessing still need deployment-specific validation. The environment was scoped to SDK testing; a full workspace make build is not claimed.

Related documentation describes the proxy's own forwarding responsibility and these limits. LiteLLM's deployment affinity and OpenRouter's provider affinity are separate layers; a missing body ID alone does not prove all existing affinity is absent.
