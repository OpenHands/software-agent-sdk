Automation observability context propagation

This PR makes SDK and agent-server conversation creation carry automation metadata and Laminar parent span context, including direct API-created conversations.

Review map Decision API before → after End-to-end flow Changed files Risks and validation

What changed

Decision: automation correlation is now treated as ambient observability context that can be read from environment variables, merged with explicit SDK metadata, serialized into HTTP headers, and rehydrated by the agent server before a conversation starts.

★ The important behavior change is that POST /api/conversations can now join an automation trace even when the custom automation bypasses the SDK and calls the agent-server API directly. See openhands-agent-server/openhands/agent_server/conversation_router.py:83 and :331.

Compatibility: additive. Existing callers may ignore the new field and headers. Existing explicit request body values continue to win over propagated header defaults.

API before → after

Before

StartConversationRequest:
  observability_metadata
  observability_tags
  observability_span_name

POST /api/conversations:
  body metadata only

Remote workspace calls:
  X-Session-API-Key only

Automation span context from LMNR_SPAN_CONTEXT stopped at the sandbox boundary unless each script manually copied it into SDK arguments.

After

StartConversationRequest:
  + observability_parent_span_context

POST /api/conversations headers:
  X-OpenHands-Observability-Metadata
  X-OpenHands-Observability-Tags
  X-OpenHands-Observability-Span-Name
  X-OpenHands-Observability-Parent-Span-Context

Remote workspace calls:
  + automation observability headers from env

The new request field is defined at openhands-sdk/openhands/sdk/conversation/request.py:261; headers are emitted from observability_headers_from_env() at openhands-sdk/openhands/sdk/observability/laminar.py:121.

Flow before → after

Changed file groups

  • core helpers openhands-sdk/openhands/sdk/observability/laminar.py adds env metadata parsing, parent context lookup, header generation, and parent-aware root span startup.
  • conversation API conversation/request.py, conversation/base.py, local_conversation.py, remote_conversation.py, and conversation.py thread observability_parent_span_context through construction and span creation.
  • remote calls workspace/remote/remote_workspace_mixin.py:77 merges automation observability headers into workspace/API requests.
  • agent server conversation_router.py:83 validates and merges observability headers; event_service.py forwards stored parent context into server-side local conversations.
  • OpenAI routes openai/router.py:82 accepts the same parent context header for OpenAI-compatible entrypoints.
  • tests Router and remote workspace tests cover direct API header handling and env-driven header propagation.

Risks and validation

  • Header trust: the agent server validates span names, tags, and metadata with existing typed adapters, and request body metadata wins over header defaults.
  • Compatibility: all new fields are optional. Existing SDK and API callers retain current behavior.
  • Validation run: targeted pytest and ruff checks passed; see PR description for exact commands.
