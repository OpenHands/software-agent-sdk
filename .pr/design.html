Issue #5264 · additive runtime contract

Canvas Apps may own one explicitly approved backend

The Agent Server now prepares and owns an optional package-declared subprocess without changing existing browser-only Apps. The critical boundary is explicit, revision-bound consent plus checksum-verified, contained execution.

★ Compatibility and security: installation, enablement, and bundle mounting still execute nothing. Only prepare(revision) then start(revision) can launch; argv is never supplied by the client or interpreted by a shell, and the resolved executable must be an executable regular file inside the prepared artifact.

Before → after

Before: browser-only

install package→enable→serve bundle

No server-owned App process lifecycle existed.

After: optional backend branch

install disabled→prepare exact revision→start owned process group→probe / logs / stop

Apps without backend stay on the original path.

States: missing · stopped · starting · ready · unhealthy · unsupported.

Trust boundary and ownership

installed manifest→SHA-256 + safe tar extraction→read-only content address→resolved contained executable
  • Contained package cwd; separate mutable data directory.
  • Only an explicit non-credential environment allowlist is inherited.
  • Per-App locks enforce one process per owning Agent Server.
  • Failed starts, stop, disable, uninstall, cancellation, and server shutdown terminate the owned process group.
  • This is process ownership, not OS isolation. Authenticated backend routing remains future issue #5265.
