DEPRECATION RUNWAY NON-BREAKING

Remove OpenVSCode from Default Agent Server

Pull Request Design Document • Resolves Issue #5266

★ Key Decision & Compatibility Impact
OpenVSCode Server is decoupled from the base Agent Server image and startup lifecycle, saving hundreds of megabytes in image footprint and memory overhead. All existing configuration flags (enable_vscode, vscode_port) and endpoints (/api/vscode/url, /api/vscode/status) remain fully backwards-compatible under a formalized 5-minor-release deprecation runway (v1.50.1 → v1.55.0). If disabled, endpoints return a clean 503 Service Unavailable with migration guidance rather than a dead editor link.

1. Before & After Architecture

BEFORE Bloated & Default Enabled
  • Docker Images: Bundled OpenVSCode Server binary (~200MB+) in default images.
  • Capabilities: ("vscode", "browser", "docker") enabled by default.
  • Lifespan: Auto-spawns background VSCodeService on startup even if no user requested an editor.
  • Failure Mode: /api/vscode/url constructed dead links if server was stopped or absent.
AFTER Lean & Deprecated Gracefully
  • Docker Images: Default capabilities stripped to ("browser", "docker"). Image builds & downloads are faster.
  • Capabilities: vscode capability is opt-in for custom builds.
  • Lifespan: enable_vscode=False by default. No idle process overhead.
  • Safety: /api/vscode/url checks is_running() and raises 503 with migration notice if unavailable.

2. API & Deprecation Schedule

Surface Change Deprecation Runway Recommended Replacement
GET /api/vscode/url Marked deprecated=True; returns 503 when not running. v1.50.1 → v1.55.0 OpenHands Standalone VSCode App
GET /api/vscode/status Marked deprecated=True; returns migration message. v1.50.1 → v1.55.0 Stand-alone extension API / health check
Config.enable_vscode Default changed from True → False. Preserved for compatibility Opt-in via OH_ENABLE_VSCODE=true
Workspace.extra_ports Docstring updated to note legacy VSCode port 8001. Preserved for compatibility Custom port forwards
@openhands/typescript-client Annotated VSCodeClient with @deprecated. v1.50.1 → v1.55.0 Canvas VSCode extension

3. Summary of Files Changed

  • openhands-agent-server/openhands/agent_server/docker/build.py & Dockerfile: Default capabilities stripped to browser,docker.
  • openhands-agent-server/openhands/agent_server/config.py: Set enable_vscode=False by default.
  • openhands-agent-server/openhands/agent_server/vscode_router.py: Marked endpoints deprecated, added 503 check for not is_running().
  • openhands-agent-server/openhands/agent_server/runtime_router.py: Propagated route deprecation flags and docstrings.
  • openhands-agent-server/openhands/agent_server/vscode_service.py: Silenced redundant startup log when disabled.
  • openhands-workspace/openhands/workspace/**: Documented extra_ports deprecation.
  • clients/typescript/src/**: JSDoc @deprecated added to VSCodeClient and manager references.
  • tests/agent_server/**: Added comprehensive unit and integration tests for disabled state, OpenAPI schema deprecation metadata, and error handling.

4. Migration Instructions

For users who rely on the built-in editor:

# To run the legacy built-in VSCode server during the deprecation period:
docker run -e OH_ENABLE_VSCODE=true -p 8000:8000 -p 8001:8001 openhands/agent-server:latest

# For custom images with the vscode capability:
python -m openhands.agent_server.docker.build --install-capabilities=vscode,browser,docker
