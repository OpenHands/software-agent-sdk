Draft · SDK settings schema · #5535

One annotated model, one structural schema

export_settings_schema() still returns SettingsSchema for GET /api/settings/agent-schema. Type, default, choices, secret-ness, and numeric bounds now come from Pydantic JSON Schema. Labels, prominence, and dependencies stay on the field annotations.

1What changed

★ Additive response fields only. Existing keys, section grouping, and the decision to keep condenser_kind visible are unchanged. minimum / applies_to / variant_selector are new optional fields on SettingsFieldSchema.

Before: _infer_value_type and _extract_choices re-walked typing. After: structural_facts reads the property, and export_settings_schema still owns sections.

2API before / after

Compatibility: additive. Clients that ignore unknown SettingsFieldSchema keys keep working. default_factory values are not emitted by JSON Schema, so the exporter still fills those from the normalized factory result.

4Condenser variants

condenser_kind stays a visible selector (variant_selector: true, choices llm_summarizing and no_op). max_size applies only to llm_summarizing. NoOpCondenserSettings.max_size is a ClassVar and is absent from that model's JSON Schema, so it is not exported. A persisted condenser payload with no condenser_kind still validates as llm_summarizing; this change does not touch that discriminator.

This draft does not decide whether Agent Canvas should hide condenser selection. That product choice stays with #5495 / #5531. The frontend rewrite that consumes these constraints is OpenHands/OpenHands#18049.

5Out of scope

  • Rewriting Agent Canvas onto raw JSON Schema.
  • Persisted settings shape, schema_version, or the API discriminator contract.
  • Regenerating the pinned TypeScript OpenAPI snapshot. New response fields are optional and appear on the live schema endpoint.
