github_ci_status — PR CI status under GitHub App tokens

New read-only tool in openhands-tools. Additive; no change to existing tools, events, or the agent-server wire contract.

Problem

gh pr checks, /commits/{sha}/check-runs, and the GraphQL statusCheckRollup all read the checks rollup. GitHub App installation tokens need Checks: read for it; Apps issued with Actions + metadata only get 403. Every automation that gates on CI then re-implements the same Actions-API polling workaround by hand.

After

One tool call does the whole chain with App-token-compatible endpoints only, and degrades gracefully when the enrichment endpoints refuse the token.

pulls/{n} → head.sha→ actions/runs?head_sha=…→ actions/runs/{id}/jobs
check-runs + statuses (best effort; 403 → permission note)

Public surface

Field (GithubCiStatusAction)Meaning
repository"owner/repo" (clone URLs normalized)
pull_number | shaexactly one; PR resolves its current head
include_jobsfetch failing job/step names for non-passing runs (default on)
Field (GithubCiStatusObservation)Meaning
overallrollup: failure > pending > success; neutral = no signals
workflow_runs, other_checksCiResult list (name, kind, status, conclusion, url, details)
unavailable_sourcesendpoints the token could not read, with permission hints

Rollup semantics

classify(signal): failure  if conclusion ∈ {failure, timed_out, action_required,
                                            cancelled, stale, startup_failure, error}
                           or state ∈ {failure, error}
                  success  if conclusion ∈ {success, neutral, skipped} or state == success
                  pending  otherwise (queued / in_progress / pending)

overall: any failure → "failure"; else any pending → "pending";
         any success → "success"; no signals → "neutral"

Failure beats pending on purpose: a gate should report "this will not be green" even while sibling runs are still going.

Token & error behavior

  • Token from conversation secrets (github_token, GITHUB_TOKEN, GH_TOKEN, github) then environment; env values are registered with the secret registry so output masking covers them. Never a tool parameter.
  • 401/403 on the core endpoints → error observation naming the missing permission (actions: read / pull requests: read).
  • 401/403 on check-runs/statuses → success path continues; the report names checks: read / statuses: read as optional.
  • GITHUB_API_URL overrides the API base (GitHub Enterprise).

Validation

  • 15 unit tests against a real local HTTP stub (tests/tools/github_ci_status/): PR→SHA resolution, failure reports with failed step names, the App-token 403 degradation path, third-party check merging, rollup precedence, pagination-safe job fetching (only for non-passing runs), token resolution order.
  • Full tests/tools suite: 1059 passed. Ruff format + lint, pycodestyle, pyright, and scripts/check_tool_registration.py pass on touched files.
