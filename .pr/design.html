Opt-in acp_strict_model: fail a session that cannot verify the selected model

additivedefault offprofile field capability-gated The contract: with the flag on, a session starts or resumes only when it can be shown to run acp_model, and the model cannot be changed on a live session.

Problem

When the ACP server rejects acp_model, _maybe_set_session_model (fresh session) and _reapply_session_model_on_resume (resume) log a warning and the session runs on the server's default model. That tolerance is deliberate (the curated model list is a suggestion, not an access check) and stays the default. A deployment that records which model ran (receipts, billing, evaluation) cannot accept it, and today the only way out is replacing four private functions.

The server's acceptance is not evidence either. In @agentclientprotocol/claude-agent-acp@0.63.0 (dist/acp-agent.js), setSessionConfigOption (L3178 to L3263) accepts an exact option, the option's current value even when it is not an option (L3209 to L3216), and a fuzzy match via resolveModelPreference (L3229 to L3239) whose substring tier (L4997 to L5011) maps "sonnettt" onto "sonnet". The _meta model seed sent with new_session is also added to the advertised options unvalidated. Live, both started sessions whose recorded model the server never ran.

Strict session start and resume

new_session(cwd=..., mcp_servers=...)            # no _meta model seed under strict
options = model options advertised by new_session / load_session
if not options:                 raise Rejected("no model options")          # nothing sent
if acp_model not in options:    raise Rejected("not one of ... options")    # exact match, nothing sent
resp = set_config_option(model=...) [, reasoning_effort=...]                # errors propagate unwrapped
set_config_option path: each value set must be present in resp and equal, else raise Rejected
set_session_model path:  no model state by protocol; the exact pre-check is the only check
  • Exact match first, so no server fuzzy matching or current-value acceptance can stand in for the request. For a Codex model/effort id the base model is matched, and both the model and the effort must be present in the final set_config_option response (which carries the session's full option state) and equal to what was set. A value the response omits fails closed, like a server that advertises no options.
  • No options means fail closed. The flag exists to give a guarantee; a server that cannot say what it offers cannot give one. claude-agent-acp returns options from both newSession and loadSession (L3970 to L3998).
  • A failure tears the session down. init_state catches the error, calls _cleanup() (terminating the subprocess), emits the typed event, sets ERROR and re-raises; _initialized and the persisted agent_state are not updated, so no turn runs on a session that failed the check.
  • No live switches. Verifying a switch on a running session needs restore, restart and turn-in-flight handling that kept producing new gaps under review (pause bypassing a running check, nothing to restore to, an unverified Codex effort on restore). The simpler contract is that a strict conversation's model is fixed once its session is verified; a different model means a new conversation, or a switch before the first run.
Trade-offs. Under strict, acp_model must be an id the server advertises for the session: a real but unlisted model (for example a full dated id when the picker shows aliases) is rejected. A server that advertises no model options, or whose load_session omits them, cannot be used with strict. Grouped select options are not flattened. Each case fails closed with a reason naming what was missing. Live model switching is unavailable with the flag on. On legacy servers that select the model with set_session_model (the UNSTABLE models capability, e.g. gemini-cli), the call returns no model state by protocol, so verification there is the exact pre-check against the advertised list only; failing closed on the missing response would make strict unusable on those servers.

Compatibility

  • All new fields default to False; payloads without the key load unchanged. No persisted-settings or profile schema bump.
  • With the flag off, every request and code path is unchanged, including set_acp_model and agent_state["acp_current_model_id"] handling. _apply_acp_model now returns its last response; non-strict callers ignore it.
  • The profile field is gated by profile_acp_strict_model_v1, following the profile_persona_v1 precedent (#5449).
