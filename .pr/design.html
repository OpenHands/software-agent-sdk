Conversation read state: server contract

This PR provides a persisted, conversation-scoped read marker in the Agent Server and its TypeScript client. It supports the backend portion of OpenHands#17140; it does not complete that issue's UI, per-user, or cross-window requirements.

Semantics and compatibility

unread = status in {finished, error, stuck}
         and (last_read_at is null or updated_at > last_read_at)

The timestamp comparison is strict: activity at the read timestamp is read. Running, idle, paused, waiting-for-confirmation and deleting conversations are not unread. Old metadata without last_read_at loads with null, so old terminal conversations initially appear unread. No persisted shape rewrite is required. The REST fields are additive; preserving updated_at on metadata edits is an intentional behavior change that downstream sort consumers should review.

Read changes invalidate the cached conversation summary, persist meta.json, and invoke the existing conversation webhook path with the complete read state. That webhook is not a browser WebSocket broadcast, and this PR does not claim immediate cross-window synchronization.

Remaining application work

  • The stored marker is shared by callers of a conversation, not keyed by user. A multi-user application must define its ownership/read-state policy before claiming independent per-user read state.
  • Canvas must consume a released server/client contract, mark conversations read on opening, and update all relevant windows through its push/state layer.
  • Canvas owns the distinct unread badge, per-item read/unread actions, mark-all-read, unread sorting, and the issue-required screenshot or video.

Regression coverage

The model tests cover every execution status against absent, older, equal and newer read timestamps. Service tests check persisted read state across restart, metadata timestamp stability and webhook payloads. The live HTTP test exercises new output, read/unread toggles, title/tag edits, list/detail consistency and a second completed response becoming unread. LLM calls use the existing deterministic fixture; no live model credentials are needed.
